# ORBY — 혼자 타는 비행기 예습 게임

비동반 소아(UM)가 공항 여정에서 **앞으로 무슨 일이 벌어질지 미리 겪어보는** 아이소메트릭 복셀 게임.
졸업 전시장 키오스크 구동이 전제다.

> **처음 보는 사람은 여기부터:**
> · Claude → [`HANDOFF.md`](HANDOFF.md)
> · 사람 → 상위 폴더의 [`작업 정리.md`](../작업%20정리.md)
> · 맵 만들기 → 상위 폴더의 [`마인크래프트 맵 제작 가이드.md`](../마인크래프트%20맵%20제작%20가이드.md)

```bash
npm install
npm run dev              # http://localhost:5173
npm run test             # NBT/좌표/RLE 단위 테스트
npm run verify           # 게임 루프 검증 (dev 서버 필요)
npm run build            # 전시용 정적 빌드 → dist/
npm run build:pages      # 깃허브 페이지 주소용 빌드 (앞가지 /orby-game/)

npm run map:import maps/파일.mcworld    # 마인크래프트 월드 → 게임 맵
npm run map:test                        # 합성 테스트 맵 재생성
npm run opening:mp4                     # 오프닝 PNG 450장 → start-loop.mp4 + start-rest.mp4
```

조작 (전시 빌드에도 있다 — 컨트롤러에 맞춰 놓은 배치다):
`C` 앞 · `D` 뒤 · `E` 왼 · `F` 오른 · `I` 고개 왼 · `G` 고개 오른 · `H` 처음으로

개발 편의 (전부 **DEV 전용** — 전시 빌드엔 없다):
`1` 패널 열기 · `2` 패널 닫기 · `Shift`+숫자 구역 점프 ·
`Shift`+`C` 미션 일괄완료 · `Shift`+`G` 보행영역 오버레이 · `?stage=N`
콘솔: `__orby` (스토어) · `__orbyCheck()` (맵 검사)

**`?diag=1` 은 전시 빌드에도 있다** — 오프닝이 지금 몇 초째인지, 어디까지
받았는지를 화면 아래에 띄운다. 아이패드에는 개발자 도구가 없어서 거기서
무슨 일이 벌어지는지 볼 방법이 이것뿐이다.

## 오프닝

**누르기 전까지 앞부분이 끝없이 돈다.** 전시장에서 아이가 오기 전까지 기다리는
화면이다 — 아무도 없는데 혼자 재생되고 혼자 게임에 들어가 있으면 안 된다.

```
창문 닫힌 채 그림자 흔들림  ──┐  무한 반복 (아무도 안 누르면 계속)
                              │
  걷기 키 아무거나 / 화면 터치 ─┘→  이번 바퀴를 마치고
                                   창문 열리는 뒷부분 (10.25초, 건너뛰기 없음)
                                   → 2구역
```

| 파일 | 원본 장 | 길이 | 용량 |
|---|---|---|---|
| `public/opening/start-loop.mp4` | 15~74번 | 3.00초 | 1.1MB |
| `public/opening/start-rest.mp4` | 75~279번 | 10.25초 | 4.9MB |

**끝은 움직임이 멎는 자리에서 끊는다.** 원본은 360번까지 가는데 **274번에서
움직임이 완전히 멎는다** — 그 뒤 86장은 같은 그림이라 마지막 컷이 4.3초간
얼어붙어 있었다. 멎고 나서 다섯 장만 남기고 279번에서 자른다. 더 줄이거나
늘리려면 `scripts/make-opening-mp4.mjs` 의 `count` 한 숫자만 만진다 (한 장 = 0.05초).

천우태가 뽑은 PNG 450장(`../시작 애니매이션`)에서 `npm run opening:mp4` 로 굽는다.
ffmpeg 같은 걸 따로 깔 필요 없다. 맥에 들어 있는 장치를 쓴다.

**"아무 버튼" 은 걷기·고개돌리기 키 여섯(`c d e f i g`)이다** — 전시 컨트롤러가
그 글자를 보내기 때문이다. 화면 터치도 받는다. `h`(처음으로)는 안 받는다.
아무 키나 받지 않는 건 일부러다 — 누가 자판을 스쳐도 안 시작된다.

**누르면 이번 흔들림 한 바퀴를 마치고** 넘어간다(최대 3초). 누른 순간이 바퀴 중
어디냐에 따라 그림자 자리가 달라서, 그냥 이으면 한 번 톡 튄다 (결정 ㊽).

**예전에는 움직이는 WebP(14MB) 한 장이었는데 아이패드에서 버벅였다.** WebP 는
브라우저가 CPU 로 한 장씩 풀어야 해서 아이패드가 따라가지 못했고, 그러면서도
걷는 시점은 **시계로** 재고 있어서 아직 돌고 있는 그림이 잘려 나갔다. 영상은
아이패드 안의 전용 칩이 풀고, 무엇보다 **끝났다고 자기가 알려준다** — 그래서
지금은 시계를 안 센다. 길이를 바꿔도 코드는 안 고쳐도 된다 (결정 ㊼).

옛 WebP 는 안 지웠다. 영상을 못 읽을 때만 그리로 돌아간다 — 그때는 WebP 가
창문 열리는 데까지 통째로 한 번 돌고, **끝나면 혼자 2구역으로 간다.**

**스플래시 마지막에서 인게임으로는 어떤 경우에도 클릭이 없다.** 2구역이 아직
안 올라왔으면 마지막 장을 붙들고 기다렸다 걷는다 — 준비 전에 걷으면 "시작하기"
버튼이 떠서 아이가 한 번 더 눌러야 한다.

## 화면 UI

`ui 가이드/Frame 276~279.png` 에서 잰 값 그대로다. 화면에 얹히는 건 **셋뿐이다.**

| 조각 | 자리 | 크기 | 만드는 곳 |
|---|---|---|---|
| 로고타입 | 좌상단 | 18u | `ui/Logo.tsx` + `public/ui/logo.png` |
| 말풍선 | 좌하단 | 67.5u × 14.2u | `ui/Companion.tsx` |
| ✦ 별 | 말풍선 왼쪽 위 모서리 | 19.7u × 29.4u | `public/ui/star.png` |
| 미니맵 | 우하단 | 26.1u 정사각 | `ui/MiniMap.tsx` + `engine/miniMap.ts` |

**틀이 보통 테두리가 아니다.** 말풍선은 **왼쪽 테두리가 없고** 오른쪽 위·아래
모서리가 비어 있다. 미니맵은 **네 귀퉁이가 다 비어 있다.** `border` 로는 안
나온다 — 모서리가 채워진다. 그래서 띠를 따로 얹는다.

로고(`로고타입 1.png`)와 별(`배경 없음 ui.png` 에서 오려낸 것)은 **천우태가 준
그림 그대로**다. 별은 SVG 로 다시 그려 봤지만 팔 두께(세로 1u·가로 2u)와 끝으로
갈수록 옅어지는 그라데이션이 안 맞아 그림을 쓴다.

글씨는 **Mona10 Regular 2.61u** 다 (가이드 44px). `python3 scripts/make-mona.py`
가 `../폰트/Mona10.ttf` 를 129KB 로 줄여 넣는다. 말풍선에만 쓰고 나머지 화면은
Pretendard 다 — 가이드가 말풍선만 이 글씨체로 그려져 있다.

**말풍선 상자는 키가 고정이다.** 글이 길면 두 줄로 들어간다. 상자가 커지면 별이
위로 밀려 가로팔이 위 띠를 못 가로지른다.

말풍선과 미니맵은 **아랫변이 같은 줄**에 있다 (`--ui-floor`). 테두리 두께도
한 값(`--ui-line`)으로 묶여 있다 — 한쪽만 고치면 한 벌로 안 보인다.

**구역 이름과 미션 체크리스트는 없앴다.** 가이드에 없다 — 할 일 안내는
말풍선이 전부 맡는다. (옛 `src/ui/Hud.tsx` 는 git 기록에 있다.)

**미니맵은 그림이 아니라 맵에서 만들어 낸다.** 한 칸에 한 픽셀씩 —
**천장을 걷어내고 위에서 본 평면도**다. 걸을 수 있는 바닥은 흰색, 못 걷는 데
서 있는 것(벽·기둥·가구)은 민트, 관문은 주황. 맵을 고치면 미니맵이 따라 바뀐다.

**UI 세 조각은 `--ui-u` 를 쓴다 — `--u` 와 다르다.** `--u` 는 7~16px 로 묶여
있어서 큰 화면에서 UI 만 제자리에 남는다(3840×2160 에서 말풍선이 45.6% 가
아니라 35.5% 였다). `--ui-u` 는 안 묶여서 **무대에 정비례**한다 — 어떤 화면에서도
가이드 비율 그대로다.

**미니맵의 위쪽은 언제나 화면의 위쪽이다.** 2·3구역은 1인칭이라(`fpv: true`)
고개를 돌리면 지도도 같이 돈다. 아이소로 여는 구역에서는 45° 로 고정이다.

UI 색은 `index.css` 의 `--ui-*` 네 개다. **블록 색(`--orby-*`)과 일부러
다르다** — 가이드의 주황·민트가 더 센데, 3D 위에 얹혀도 묻히지 않으려면 그래야
한다. 블록 색은 맵에 구워진 값이라 같이 건드리면 안 된다.

## 웹에 올리기

<https://snake0120-dev.github.io/orby-game/>

```bash
npm run deploy                          # 빌드해서 웹 주소를 새 것으로 바꾼다 (1~2분)
git add -A && git commit -m "무엇을 고쳤는지" && git push    # 코드도 올린다
```

둘은 따로다 — `deploy` 는 **보이는 화면**을, `push` 는 **코드**를 올린다.
화면만 바꾸고 싶으면 `deploy` 만 하면 된다.

**저장소 이름을 바꾸면 세 군데를 같이 바꿔야 한다** — 페이지 주소 뒤에 저장소
이름이 붙기 때문이다. `scripts/deploy-pages.mjs` 의 `BASE`, `package.json` 의
`build:pages`, 그리고 이 문서. 안 바꾸면 맵·오프닝 영상·글꼴을 빈 데서 찾아
**까만 화면**이 된다.

전시장 키오스크는 오프라인이라 이 주소를 안 쓴다 — `npm run build` 한 `dist/`
폴더를 아이패드에 직접 띄운다. 이 주소는 **보여주기용**이다.

## 맵은 마인크래프트로 만든다

```
마인크래프트(휴대폰)에서 짓기
  → 구조 블록 "저장"          (월드 안에 기록. iOS는 Export가 막혀 있어 이 경로가 유일)
  → 월드를 .mcworld 로 내보내기 (아이폰·안드로이드 모두 가능)
  → npm run map:import
  → public/maps/*.json
```

**아이 키 = 8블록.** 1블록 = 게임의 1복셀 = 0.1 월드유닛. 통로는 최소 4블록 폭.

마커 블록 (화면에 안 그려진다 — 바닥 위에 놓는다):

| 블록 | 뜻 |
|---|---|
| 흑요석 | 걸을 수 있는 칸 |
| 레드스톤 블록 | 시작 위치 |
| 에메랄드 블록 | 관문 |
| 금 / 다이아 / 청금석 / 철 블록 | 물건 자리 ①②③④ |

**마인크래프트는 "어디"만, 스테이지 파일이 "무엇"을 담당한다.** 미션·대사·순서는
`src/game/stages/*.ts` 에 있어서 맵을 다시 임포트하지 않고도 계속 고칠 수 있다.

색은 `src/game/blocks.ts` 에서 매핑한다. 임포터는 색을 모르기 때문에 이 파일만 고치면
재임포트 없이 바로 반영된다. 콘크리트는 실제 텍스처 색이라 **지은 그대로 보인다.**

## 설계 원칙

**실패 상태가 없다.** 타이머·죽음·감점이 없다. 순서가 아닌 걸 만지면 막는 대신
동반자가 "먼저 ○○부터 하자"고 안내한다. 불안을 줄이려고 만든 서비스가
게임 안에서 아이를 벌주면 앞뒤가 맞지 않는다.

**색이 곧 조작법이다.**
- 오렌지 `#F89B23` → 아이가 **만질 수 있는 것**
- 틸 `#2DC4B6` → **길을 알려주는 것** (관문, 큐브 사인, 동반자 ✦)

플레이 테스트에서 조작을 못 찾으면 UI가 아니라 이 규칙이 깨진 것이다.

**관문은 탈출구가 아니라 이정표다.** 각 구역 출구는 기획 솔루션 01의 웨이파인딩
큐브 사인이다. 실제 공항에 설치될 그 사인과 같은 모양이라 아이가 현장에서 알아본다.

## 구조

```
scripts/     .mcworld 임포터 + NBT 파서 + 검증 도구
src/engine/  스테이지에 무관한 재생 장치 (렌더·길찾기·카메라)
src/game/    스테이지 데이터 · 상태머신 · 블록 매핑 · 검사기
src/ui/      HUD · 말풍선 · 전환 화면
```

DEV에서 맵을 불러올 때 검사기가 자동으로 돌고 콘솔에 한국어로 문제를 알려준다.
특히 **흑요석이 끊겨 길이 막힌 것**은 눈으로 안 보이므로 연결성을 BFS로 확인한다.
